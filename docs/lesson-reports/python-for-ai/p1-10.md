## 2. Curriculum alignment

- **Learner outcome:** Say what a module and a package are, import a module in three styles and say which name each style creates in the file, and use `json.loads` to turn a JSON object held as text into a dict. (Curriculum entry P1.10 "Modules and packages", needs P1.9. The curriculum snapshot holds only the title and prerequisites, so the outcome wording is the author's.)
- **Misconception addressed:** (a) After `import tags` you can call `label(...)` directly. The import created only the name `tags`. (b) JSON text looks like a dict, so `reply["topic"]` works. It is a `str` until `json.loads` builds a dict from it.
- **Prerequisites and adjacent lessons:** P1.9 (functions; its web lesson is still in draft PR #57), P1.6 (dictionaries), P1.1 (`type()`, `str`). Next: P1.11 (errors and safe parsing), then P1.12 (pandas).
- **Out of scope (deliberately left to other lessons):** installing packages and pip, virtual environments, `from x import *`, `__init__.py` (named once, not explained), relative imports, `json.dumps`, invalid JSON and `try`/`except` (P1.11, one-line pointer only).

## 5. Decisions and deviations

- **Own-file running example.** The module and package sections use the learner's own `tags.py` and a `helpdesk` folder, so "a module is typically a file" is concrete before the standard library appears. The alternative was to use only `json` and `math`. `math.sqrt` was avoided because it adds arithmetic.
- **One criterion for the categories:** what each thing holds (function: steps; module: functions; package: modules). The nested relation "a package is a kind of module" is stated in the roadmap, the package section, a quick question and the takeaway. File and folder are given as typical arrangements, not definitions.
- **"Fresh file" assumption** is stated in the running-example box, both quiz questions and the lab, because the name-creation claims hold only when no other names exist.
- **Four images, none in the stdlib or styles sections.** The styles section uses three code cards, since exact code is more reliable as text. The stdlib section is short and has a plain list.
- **No transition on the lab buttons.** A colour transition made the hover-contrast test read a mid-animation colour, so it was removed.
- **Mobile repo read for scope only.** The mobile spec's headings were read for the topic list. No text, example or question was copied.
- **Previous lesson not linked.** P1.9's web lesson is not merged, so this lesson links only to the chapter page.
