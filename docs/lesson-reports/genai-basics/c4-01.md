- **Interaction:** `SupervisedLab` provides a two-mode interactive walk-through with Reset:
  1. *Spot inputs & target*: three everyday scenarios (Sam's spam filter, Apartment rent estimate, Parcel delivery check), each stating prediction time and supplied clues; clicking any item reveals option-specific feedback in a live region and, when solved, tags Target vs Input badges.
  2. *Trace a new email*: three preset incoming emails plus individual clue toggles (`Known sender?`, `Unknown link?`, `Urgent payment?`) evaluated against Sam's six invented past labeled emails via an explicitly disclosed nearest-match voting rule, highlighting matching rows and showing the vote tally and predicted target.
- **Knowledge check:** Neighbourhood clinic missed-appointment scenario testing both input-vs-target identification at prediction time and the misconception that all machine learning needs supplied labels. Correct option at index `1` (varied from other lessons). Wrong feedback:
  - Index `0`: explains that whether a text-message (SMS) reminder was already sent at prediction time is supplied one day ahead as an input, not the outcome being predicted.
  - Index `2`: explains that days booked in advance is already known one day ahead and supplied as an input, and being numeric does not make a column the target.
  - Index `3`: confirms the learner identified the target and inputs correctly, then corrects the misconception by noting unsupervised, self-supervised, and reinforcement learning learn from other training signals.

## 5. Decisions and deviations

- **Shared `data.ts` module:** Next.js 16 Server Components cannot import plain array constants from a `"use client"` module (`SupervisedLab.tsx`), so `TRAINING_EMAILS` was placed in `src/lessons/genai-basics/c4-01/data.ts` for clean import by both `Lesson.tsx` and `SupervisedLab.tsx`.
- **Two-mode lab layout:** Split "Spot inputs & target" and "Trace a new email" into two mode buttons rather than stacking both simultaneously, keeping the 390px phone layout uncluttered and easy to correlate.
- **Image provider fallback:** Followed `references/tooling.yaml` `image_generation.order` (`[agy-gemini, codex]`): `agy-gemini` generated the initial v1 images, then hit `429 RESOURCE_EXHAUSTED` (`gemini-3.1-flash-image`) when regenerating the v2 images after Content Review Round 1, so `codex` was used as the documented fallback for the three v2 images. All three final WebPs were visually verified via `read_file` to contain exact quoted text, accurate arrows, and two distinct side-by-side bottom cards (`Analogy` left, `Key takeaways` right).
- **Review provider fallback in Round 4:** Followed `references/tooling.yaml` `review.order` (`[codex, agy-gemini, claude-haiku, separate-agent]`): Codex (`gpt-6.2-sol`) ran Plan R1–R2 and Content R1–R3, then hit its usage limit mid-way through Content R4, so `agy-gemini` (`gemini-4-neon-medium`) ran Content R4 cleanly.
