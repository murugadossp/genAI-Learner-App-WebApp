## 3. What was built

- **Files added:** `src/lessons/genai-basics/c2-09/{meta.json,Lesson.tsx,SamplingLab.tsx,lesson.module.css,sampling.ts,images/{temperature,top-k,top-p,pipeline}.png}`, `tests/web/c2-09.spec.ts`, this report.
- **Explanation sections:** a "where" section explains that the network's final layer outputs one logit per vocabulary token, that temperature is a post-processing step applied to those logits (weights untouched, no retraining), and that the process repeats per generated token. It has a code-drawn two-zone diagram (inside the network, sampling step) and a worked table of the lab's invented logits at T = 1 and T = 0.5, computed by the same softmax function the lab uses. A "settings" section explains temperature (reshapes every bar), top-k (keeps a fixed number by rank) and top-p (keeps enough to cover p, so the count adapts), each with an illustration. A "mix" section shows a pipeline illustration and says real systems can combine the settings, that order matters, and that implementations differ.
- **Images:** four illustrations generated with Codex (image generation), resized to 1200x800 PNG. Each has descriptive alt text and a caption saying it is schematic. Text inside the images is limited to short labels, checked by eye for exactness.
- **Interaction:** a temperature slider (0 to 2) reshapes invented scores for two prompts: an open-ended story line and a factual prompt where the invented model's top choice is a wrong answer. A trim option (none, top-k 3, top-p 80%) removes choices and renormalises. A table shows each chance and counts from 20 seeded draws; "Draw 20 again" changes the seed; reset restores defaults.
- **Knowledge check:** correct option is position 3 of 4 (index 2). Wrong 1: top token is a guess, not a verified fact. Wrong 2: temperature triggers no checking. Wrong 4: safety comes from training and application controls.
- **Shared code touched:** none. The chapter 2 label and links fit this lesson.

## 5. Decisions and deviations

- The factual prompt uses an invented model that is wrong, so the lab can show low temperature making a wrong answer more certain. The real-world capital is stated only as the "(correct)" label.
- Playwright's port 3100 was held by another worktree's dev server (c2-10), so the full suite was run with a temporary config on another port. The committed config is unchanged.

- Independent Codex review, run until approval: a standard pass (clean), then adversarial passes. Findings fixed: the redraw was not announced to screen readers, copy claimed raising temperature always helps the right answer (the lab shows it peaks near 1), small probabilities rounded to 0% and looked trimmed, and the disclosure ranked the wrong answer second. The last pass approved.
- Later Codex rounds, on the added illustrations and the "where" section, found and fixed: the top-p illustration cut off at about 76% instead of 80% (regenerated and measured), the wording "the whole sequence runs again" ignored cached computation (reworded), and a claimed 320px table clip that was measured and not reproduced (a containment test was added instead). The final round approved.
- Review notes handled: the correct quiz option no longer stands out by length, and the sentence about compounding now says the lab does not show it.

- Hydration warning found by the user in the dev server: the probability bar width was an unrounded float (for example 2.199007193577985%), which the server and browser formatted differently. The width is now rounded to 0.1%, the same as the printed percentage. Reproduced in dev with the old code (1 console error) and confirmed fixed (0 errors). The Playwright suite runs against the production build and did not catch this with the old code, so the new console-error assertion is a general safeguard, not a regression test for this exact bug.
